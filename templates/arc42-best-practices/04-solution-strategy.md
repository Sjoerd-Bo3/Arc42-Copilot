# 4. Solution Strategy

> **Purpose**: Summarize the fundamental decisions and solution approaches. This is the "why did you build it this way?" chapter. Each decision should trace back to a quality goal or constraint.

## Core Decisions

| | | |

> **Tip**: Structure each decision as: "We chose X *because* quality goal Y requires Z." This creates traceability.

> **Tip**: Keep this short — 5-10 key decisions max. Details go in ADRs (Chapter 9).

> **Anti-pattern**: Listing technology choices without rationale. "We use React" is not a strategy. "We use React because we need fast iteration on the workshop UI (Usability goal)" is.
